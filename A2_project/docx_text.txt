A2: Ikki Ubuntu Server O‘rtasida Ko‘p Qatlamli Himoyalangan Aloqa Kanalini Yaratish
Laboratoriya ishining asosiy maqsadi:Ushbu laboratoriya ishining bosh maqsadi — kompyuter tarmoqlarida axborot xavfsizligini ta’minlashning eng muhim ustunlari bo‘lgan SSH (Secure Shell), TLS (Transport Layer Security) va IPsec (Internet Protocol Security) kriptografik protokollarini real Linux muhitida amaliy sozlash, ularning o‘zaro ishlash mexanizmini va himoya qamrovini tadqiq qilishdan iborat.
Amaliyot davomida talaba:
OpenSSH xizmatini parolsiz, zamonaviy elliptik egri chiziqqa asoslangan ED25519 asimmetrik kalitlari asosida sozlaydi va server xavfsizligini kuchaytiradi (hardening).
O‘zining shaxsiy Lokal Sertifikatlash Markazini (Local CA) quradi, X.509 v3 standartidagi zamonaviy SAN (Subject Alternative Name) maydoniga ega raqamli sertifikat ishlab chiqadi va Nginx veb-serverida faqat xavfsiz TLS 1.2 / TLS 1.3 protokollarini yoqadi.
Linux yadrosining XFRM moduli va strongSwan dasturiy ta’minoti yordamida ikkita host o‘rtasida IKEv2 va ESP (Encapsulating Security Payload) transport rejimiga asoslangan IPsec tunnelini o‘rnatadi.
Har bir protokolning to‘g‘ri ishlashini ijobiy (positive) sinovlar bilan tasdiqlaydi hamda ataylab kiritilgan xatoliklar orqali nazoratli salbiy (controlled negative) sinovlar o‘tkazib, xavfsizlik mexanizmlarining rad etish qobiliyatini tekshiradi.

2-QADAM: WEBSRV da SSH Hardening (Xavfsizlikni kuchaytirish)
Ushbu qism websrv (192.168.57.20) terminalida bajariladi.

3-bosqich: Lokal CA va TLS server sertifikatini yaratish (SAN bilan)
Bosqichning mohiyati va mantiqiy zanjiri
Ildiz CA (Root CA): O‘zining maxfiy kaliti (ca.key) va o‘zini o‘zi imzolagan sertifikatiga (ca.crt) ega bo‘ladi. Mijoz (LAN-CLIENT) ushbu ca.crt ga ishonsa, ushbu CA imzolagan barcha keyingi sertifikatlarni ham avtomatik ishonchli deb biladi.
Server kaliti va so‘rovi (CSR): Veb-server o‘zining shaxsiy kalitini (srv1.key) va imzolash uchun arizasini (srv1.csr) tayyorlaydi.
SAN kengaytmasi (srv1.ext): Zamonaviy brauzerlar va curl vositasi faqat CN maydoniga ishonmaydi; sertifikat ichida aniq domen (srv1.a2.lab) va IP manzil (192.168.57.20) ko‘rsatilgan SAN bloki bo‘lishi shart.
Imzolash: CA o‘zining muhri bilan server arizasini tasdiqlab, tayyor srv1.crt ni chiqaradi
Bajariladigan amallar (websrv terminalida)
1-qadam: Katalog tayyorlash va Ildiz CA yaratish
Xavfsiz, faqat root o‘qiy oladigan katalog ochamiz va CA kaliti bilan sertifikatini generatsiya qilamiz:
sudo install -d -m 700 /etc/a2-tls
cd /etc/a2-tls
sudo openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out ca.key
sudo openssl req -x509 -new -sha256 -days 365 -key ca.key -out ca.crt -subj "/C=UZ/O=A2 Lab/CN=A2 Lab CA"
davomidan Server maxfiy kaliti va so‘rovi (CSR) ni yaratamiz
Endi Nginx veb-serveri foydalanadigan kalit va arizani generatsiya qilamiz: (6-rasm)
Bash
cd /etc/a2-tls
sudo openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out srv1.key
sudo openssl req -new -key srv1.key -out srv1.csr -subj "/C=UZ/O=A2 Lab/CN=srv1.a2.lab"
6-rasm.

5-bosqich: strongSwan orqali IKEv2/IPsec transport rejimini sozlash
Bosqichning mohiyati va maqsadi
Transport rejimini sozlash: Tunnel (Gateway-to-Gateway) emas, balki ikki server (websrv: 192.168.57.20 va LAN-CLIENT: 192.168.57.10) o‘rtasida to‘g‘ridan-to‘g‘ri Transport Mode o‘rnatish.
IKEv2 va PSK autentifikatsiyasi: Boshqaruv kanali (Control Plane) uchun xavfsiz IKEv2 protokolidan va umumiy maxfiy kalitdan (Pre-Shared Key) foydalanish.
SA (Security Association) o‘rnatilishi: Ikkala tomonda ham IKE SA va Child SA (ESP) ulanishlarini to‘liq o‘rnatish (ESTABLISHED / INSTALLED).
Paketlar sathida isbotlash: tcpdump orqali tarmoqda IP paketlari ochiq emas, ESP (Encapsulating Security Payload) protokoli bilan shifrlanib o‘tayotganini qayd etish.
1-qadam: websrv da konfiguratsiya faylini yaratish
websrv terminalida faylni oching:
sudo nano /etc/swanctl/conf.d/a2-ipsec.conf
Ichiga quyidagi blokni to‘liq joylashtiring:
connections {
srv1-client1 {
version = 2
local_addrs = 192.168.57.20
remote_addrs = 192.168.57.10
local {
auth = psk
id = srv1
}
remote {
auth = psk
id = client1
}
children {
transport-net {
mode = transport
start_action = none
}
}
}
}
secrets {
ike-srv1 {
id-1 = client1
secret = "A2LabSuperSecretKey2026"
}
}
2-qadam: Ruxsatni to‘g‘rilash va yuklash
sudo chmod 600 /etc/swanctl/conf.d/a2-ipsec.conf
sudo swanctl --load-all

7-bosqich: Nazoratli xatolik sinovi: Noto‘g‘ri PSK va tizimni tiklash
Oldingi bosqichlarda IPsec xavfsiz kanali to‘g‘ri ishlashi tekshirildi. 7-bosqichning asosiy maqsadi — salbiy sinov (negative testing / fault injection) o‘tkazishdir.
Axborot xavfsizligida tizim faqat to‘g‘ri ma'lumotlar bilan ishlashini emas, balki buzilgan yoki begona ulanishlarni qanday rad etishini tekshirish juda muhim:
Autentifikatsiya mexanizmining ishonchliligi: Agar tajovuzkor yoki begona tugun noto‘g‘ri Pre-Shared Key (PSK) ishlatsa, IKEv2 protokoli seansni darhol to‘xtatishi (AUTHENTICATION_FAILED) va unga hech qanday ESP shifrlash kalitlarini bermasligini isbotlash.
Kuzatuvchanlik (Audit va Loglar): Xavfsizlik hodisasi yuz berganda strongSwan jurnalida (journalctl / charon loglari) qanday xato yozuvlari qolishini ko‘rish va qayd etish.
Tizimni tiklash (Disaster Recovery / Rollback): Xatolik yuz bergandan so‘ng konfiguratsiyani yana asl holatiga qaytarib, xizmatni qayta ko‘tarish amaliyotini mustahkamlash.
1-qadam: LAN-CLIENT da PSK kalitini ataylab buzish
LAN-CLIENT (192.168.57.10) terminalida mavjud ulanishni to‘xtatib, noto‘g‘ri kalit kiritamiz:
Avval mavjud ulanishni uzing:
sudo swanctl --terminate --ike client1-srv1
Verification: terminate completed successfully chiqadi.
