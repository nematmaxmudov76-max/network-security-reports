0 Talaba bajaradigan dastlabki tayyorgarlik
O‘qituvchining tayyorgarlik vazifasi — ishlaydigan VMware obrazini tayyorlab, fayl serverga joylashtirish.
VMware Workstationni o‘rnatish, obrazni ko‘chirish va ochish, VM nusxalarini ajratish, tarmoq va proksini
sozlash, paketlarni o‘rnatish, xizmatlarni ishga tushirish hamda snapshot olishni talabaning o‘zi bajaradi.
Birinchi marta bajariladigan bu ishlar asosiy 80 daqiqalik tahlildan oldin yakunlanadi. Taxminiy tayyorgarlik vaqti
40–60 daqiqa; fayl ko‘chirish, arxivni ochish va paket yuklash tezligiga qarab uzayishi mumkin. Tayyor obraz
mavjudligi paketlar va laboratoriya tarmog‘i oldindan sozlanganligini anglatmaydi.

ikkinchi adapter qo‘shing va Custom: Specific virtual network → VMnet2 ni tanlang. Tayyor obrazdagi ortiqcha

VMni yoqing. Quyidagilar bilan interfeyslarni aniqlang. VMware interfeyslari ens33, ens37 yoki boshqa nomda
bo‘lishi mumkin; nomlarni taxmin qilmang. ip -br link dagi MAC manzilni VM Settings → Network Adapter →
Advanced dagi MAC bilan solishtirib, NAT va laboratoriya interfeysini ajrating.
ip -br link
ip -br addr
ip route
ip route get 172.18.1.1

NAT interfeysi VMnet8 DHCP xizmatidan IP va default route olishi kerak. Proksi manziliga marshrut NAT
interfeysidan chiqadi. VMga 172.18.1.1 manzilini IP yoki gateway qilib bermang: bu universitet proksi serverining
manzili. DHCP orqali olingan gateway saqlanadi.
NAT da IPv4 manzil olinmasa, avval VMware DHCP/NAT xizmatlari va adapter ulanishini tekshiring. Ubuntu
Serverda sudo netplan get va /etc/netplan/*.yaml orqali mavjud konfiguratsiyani ko‘ring. NAT interfeysining
amaldagi yozuvida dhcp4: true bo‘lsin. Eski nom yoki MACga bog‘langan yozuvni yangi NAT interfeysiga
moslang; mavjud faylni avval nusxalab oling. O‘zgartirishni sudo netplan try bilan sinab, konsolda tasdiqlang. Bir
interfeys uchun bir-biriga zid yangi YAML yozuvlarini ko‘paytirmang.
Paket o‘rnatishni dastlab SEC-ANALYST da, keyin SRV-1 da ketma-ket bajaring. Tayyor obrazdagi DHCP
identifikatori nusxalarda bir xil bo‘lib qolgan bo‘lsa ham, bittadan yoqib sozlash NAT manzili to‘qnashuvini
chetlab o‘tadi. Asosiy ishda NAT uziladi va SEC-LAB uchun turli statik manzillar beriladi.

0 5 Universitet proksisini ikkala VMda sozlash
Quyidagi buyruqlar har bir Ubuntu VM terminalida bajariladi. export joriy shell va undan ochilgan dasturlarga
ta’sir qiladi; yangi terminal yoki qayta yuklashdan keyin kerak bo‘lsa takrorlang. Bu sozlama barcha dasturlarni
avtomatik ravishda proksidan o‘tkazmaydi.
export http_proxy="http://172.18.1.1:2500"
export https_proxy="http://172.18.1.1:2500"
export HTTP_PROXY="http://172.18.1.1:2500"
export HTTPS_PROXY="http://172.18.1.1:2500"

Lokal laboratoriya manzillariga murojaat proksiga ketmasligi uchun quyidagilarni ham kiriting:
export no_proxy="localhost,127.0.0.1,192.168.56.10,192.168.56.20"
export NO_PROXY="$no_proxy"

https_proxy qiymatida ham http:// yozilishi to‘g‘ri: mijoz HTTP proksiga ulanadi, HTTPS saytga tunnel orqali
murojaat qiladi. sudo orqali ishlaydigan APT uchun alohida doimiy konfiguratsiya yarating. Agar 99proxy
avvaldan mavjud bo‘lsa, uni avval o‘z uy papkangizga zaxiralang.
sudo tee /etc/apt/apt.conf.d/99proxy >/dev/null <<'EOF'
Acquire::http::Proxy "http://172.18.1.1:2500";
Acquire::https::Proxy "http://172.18.1.1:2500";
Acquire::ftp::Proxy
"http://172.18.1.1:2500";
EOF

EOF satri alohida va boshida bo‘sh joysiz yoziladi. HTTP/HTTPS parametrlari Ubuntu paketlarini yuklashda
ishlatiladi; FTP satri berilgan universitet konfiguratsiyasiga muvofiq saqlandi, ushbu A1 da FTP tekshirilmaydi.
APT fayli terminal yopilganda ham saqlanadi.
apt-config dump | grep -i proxy
sudo apt update

sudo apt update ombor indekslarini muvaffaqiyatli yangilashi kerak; proksi yoki ombor xatolari bo‘lsa, keyingi
bosqichga o‘tishdan oldin ularni hal qiling. ping 8.8.8.8 ishlamasligi HTTP proksi nosozligini isbotlamaydi: ping
ushbu proksi orqali ishlamaydi.

0 6 Paketlar va xizmatlarni talaba tayyorlashi
SEC-ANALYST da:
sudo apt install -y nmap curl iproute2 iputils-ping
nmap --version | head -n 1

SRV-1 da:
sudo apt install -y openssh-server nginx ufw curl iproute2 iputils-ping
sudo systemctl enable --now ssh nginx
systemctl is-active ssh nginx

Natijada ssh va nginx uchun active chiqishi kutiladi. SRV-1 da curl ham o‘rnatiladi, chunki u lokal xizmat va
HTTP dalilini tekshirishda ishlatiladi. UFW holatini hozircha o‘zgartirmang. apt update paketlar ro‘yxatini
yangilaydi; bu barcha paketlar yangilanganini anglatmaydi. A1 da majburiy to‘liq apt upgrade talab qilinmaydi.
curl o‘rnatilgach, tashqi HTTP/HTTPS so‘rovini tekshirish mumkin:
curl -I --max-time 20 https://ubuntu.com

Saytdan HTTP javob kelishi proksi yo‘li ishlayotganini ko‘rsatadi. 407 — proksi autentifikatsiyasi talabi; timeout
— NAT, marshrut yoki proksiga yetib borish muammosi bo‘lishi mumkin. Proksi qo‘shimcha hisob talab qilsa,
fileuser rekvizitlarini avtomatik qo‘llamang.

Risk bayonoti qolipi. “Agar [tahdid manbai] [zaiflik]dan foydalansa, [aktiv]ga [oqibat] yuz beradi va
[maxfiylik/yaxlitlik/mavjudlik] buziladi.” Riskni faqat “port 22 ochiq” kabi kuzatuv bilan tenglashtirmang: ochiq
port dalil, risk esa ssenariy va oqibatdir.

Misol orqali risk va qoldiq riskni hisoblash
Faraz qilaylik, curl natijasi ichki portal HTTP orqali ishlayotganini ko‘rsatdi. Tarmoqdagi buzilgan host trafikni
kuzatishi yoki o‘zgartirishi mumkin. Laboratoriyada haqiqiy maxfiy ma’lumot yo‘q, biroq ishlab turgan ichki portal
uchun E=3 va T=2 deb asoslash mumkin: R=3×2=6, ya’ni o‘rta risk. TLS joriy etilib, sertifikat tekshiruvi majburiy
qilinsa ehtimollik E=1 gacha tushadi; T=2 o‘zgarmasa qoldiq risk 2 bo‘ladi. Bu faqat metodik namuna — talaba
qolgan risklarni o‘z dalili asosida baholaydi.

1 7 Tahdid modelini tuzish
Har bir muhim aktiv uchun kamida bitta tahdid manbai, kirish yo‘li, zaiflik yoki noaniq nazorat va mumkin bo‘lgan

foydalanib, qaysi aktivga qanday zarar yetkazishini ko‘rsatishi kerak.

• Buzilgan ichki foydalanuvchi kompyuteri: SEC-LAB ga kirish imkoniga ega va ochiq xizmatlarni izlaydi.
• Ruxsatsiz ichki shaxs: hisob ma’lumotini taxmin qiladi yoki boshqa foydalanuvchining sessiyasidan
